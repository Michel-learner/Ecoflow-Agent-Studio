01

场景与痛点

为什么跨市场内容生产是 EcoFlow 的核心挑战

EcoFlow 同一款储能产品需要面向 北美、欧洲、日本 等市场， 在 Instagram、KOL 和独立站 等渠道持续生产内容。 不同市场的灾害环境、能源需求、消费动机和表达习惯存在差异， 内容生产需要同时理解市场、核对产品事实、适配渠道并承接独立站转化。

信息分散

产品资料、市场事件、UGC 和历史内容表现分布在不同来源，内容团队需要反复检索和判断。

产品手册 社媒 UGC 市场报告 历史素材

生成不可追溯

普通 AI 能生成文案，但关键结论与市场证据、产品参数和素材来源缺少明确映射。

文案 → ❓ → 证据来源 数据 → ❓ → 产品事实

经验难以复用

投放结束后只能看到曝光、点击和转化，难以继续追溯高表现内容使用了哪条证据、哪种素材和哪套表达结构。

高转化内容 → ❓ → 哪条证据 好表现 → ❓ → 能否复用
核心问题

并非缺少内容生成工具，而是缺少一条能够连接市场证据、内容生产、质量审核和效果复用的营销工作流。

飞书多维表格承载与全链路协同

正在解决：方案如何基于飞书产品矩阵真实落地，而不只是概念

整套方案的每一步输出都落地在飞书多维表格中， 五张核心数据表（Evidence / Copy / QA / Performance / Asset）通过关联字段串起全链路 ID， 让证据、文案、审核、表现、资产彼此可追溯。

飞书 Aily 作为 AI Harness 的执行引擎，读取多维表格中的任务上下文， 按顺序调度四个 Agent，并将结果回写到对应数据表； 飞书自动化监听字段变化触发下一阶段； 飞书审批卡在高风险节点做人工闸门。

📌 落地实施步骤

  1. 建表：在多维表格中创建 5 张核心表，配置字段类型与关联关系
  2. 配 Agent：在飞书 Aily 中分别搭建 Agent A/B/C/D，绑定对应多维表格数据源
  3. 接自动化：用飞书自动化监听「阶段状态」字段变更，触发下一阶段 Agent 运行
  4. 加审批：高风险内容和正式发布前插入飞书审批节点，人工确认后才流转
  5. 做看板：基于多维表格视图生成团队看板，实时查看任务进度和资产沉淀

01

四个 Agent 的 Prompt 摘要

  • Agent A · 证据检索：指令聚焦来源分层、时效标注、市场范围确认，输出结构化 Evidence
  • Agent B · 内容生成：仅基于可用证据生成，输出 Claim ↔ Evidence 映射，禁止无依据结论
  • Agent C · 内容审核：引用核查、产品事实校验、品牌合规、市场边界四维度逐项检查
  • Agent D · 营销转化：效果对比 → 反向追溯 → 资产卡沉淀 → 下一轮推荐四步走
02

五张核心数据表字段总览

Evidence：evidence_id · source · level · market · time · status Copy：copy_id · channel · claim · evidence_ref · material_id QA：qa_id · copy_id · check_items · issue_loc · pass/reject/revise Performance：perf_id · copy_id · impressions · CTR · CVR Asset：asset_id · scene · market · performance · reusability
03

Agent A 来源分层与时效规则

T1 官方产品参数、官方文档、品牌数据
T2 可靠权威媒体、行业报告、政府统计
T3 社媒UGC、达人反馈、趋势信号（需人工确认）

产品事实内容仅允许使用 T1/T2 来源；T3 作为选题与方向参考，不直接作为事实依据。
